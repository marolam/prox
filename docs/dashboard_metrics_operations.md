# Dashboard metrics

Read-only live inspection on 2026-10-05 confirmed `dashboard/metrics` contained `totalUsers: 8`, `newUsersToday: 0`, and `updatedAt: 2026-04-10T08:42:03.373Z`. It had no business/payout/coverage fields. A read-only aggregate counted 34 current user documents. Cloud Functions returned 404 for `recomputeDashboardMetrics`, and the Cloud Scheduler list contained no matching job. No production statistics were changed during inspection.

The old frontend returned a constant empty `DashboardMetrics`, so both Business HQ and Network Pulse always showed invented zero counts. It now subscribes to the server-owned `dashboard/metrics` document. Missing/error/loading states are explicit. A snapshot older than three hours is identified as out of date and its values are unavailable as current metrics. Missing fields remain unavailable; a genuine fresh zero remains zero. Daily values additionally require the current UTC date, preventing a fresh previous-day snapshot from claiming to describe today. The last refresh timestamp remains visible for stale snapshots.

The existing `recomputeDashboardMetrics` export must be deployed through the selected Functions target and its hourly UTC Scheduler trigger verified. It reads current non-deleting user documents, trusted Auth registration timestamps, exact `users/{uid}/billing/entitlements` documents, current paid active business access, presence, profiles, and existing legacy credited referral/technician-support payout sources. Missing Auth users do not invent new registrations; Auth lookup errors fail the refresh. A failed refresh cannot stamp zero values as fresh.

Business mode first activation is recorded server-side in `businessModeEnabledAt` on an actual activation transition and retained through retries/reactivation. Already-active legacy accounts without a trusted activation date remain unknown. If any active account lacks that date, `newBusinessModeUsersToday` is omitted and the frontend shows unavailable; `businessActivationDatesKnown` and `businessActivationDatesUnknown` document coverage. `updatedAt` is never treated as an activation date.

Metrics and keyword-count snapshots commit in one Firestore batch. Keyword counts derive from the canonical current user projection, with legacy profile fallback only for accounts lacking modern keyword fields; explicitly cleared modern keywords stay cleared. Presence and referral groups are read without field filters and validated in memory, avoiding hidden collection-group index dependencies for this small early population. The job already scans the user/profile population; a future scale change should move aggregates to incremental server events. Protected account deletion markers, orphan/foreign path checks and current paid access prevent stale legacy documents from inflating coverage or business totals. Existing payout totals continue to describe credited referral and legacy technician-support payouts, as before; they are not a sum of every platform bonus or purchase.

After targeted deployment, verify the hourly job exists/enabled, invoke only the authorized scheduled handler if an immediate refresh is desired, then read `dashboard/metrics.updatedAt` and aggregate counts to confirm freshness. Verify Business HQ on-device displays refreshed data, and that rollback removes any newly created handler/Scheduler resources and restores the prior frontend build. This change does not invoke the handler or enable a production job automatically.
